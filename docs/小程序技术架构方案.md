# 有数 · 小程序技术架构方案（v1）

> 配套：《产品定位与 MVP 规划》《产品调研报告》《AGENTS.md》设计铁律。
> 状态：草案 v0.3（已确认：10000 容量上限、uuid、导入覆盖+可滚动明示清单、云同步/订阅未来一起做、分类分布双维度）。原型迭代已完成（v4 极简墨为定稿方向，见 `prototype/`）。

## 0. 设计约束（来自已确认决策）

- **形态**：微信小程序（免安装、跨平台、可免费无广告）。
- **v1 范围**：极简手工录入 + **纯本地存储** + 导出/导入（JSON，界面不暴露 JSON 字样）。
- **v1 明确不做、且代码里不写**：云端同步、订阅付费、额度拦截、AI、录音、拍照/条码识别。
  - v1 的"我的"页只有：**导出数据 / 导入数据 / 关于**，不出现任何订阅或云同步入口。
- **未来会做（v1 之后）、但 v1 不写业务代码**：**云端同步与订阅付费——两者未来一起做、同版本上线**（含额度 `FREE_LIMIT=50`、价格 `SUB_PRICE=1`，届时由服务端下发，不硬编码在 v1）。
- **扩展方式（核心）**：v1 只通过"架构扩展点"预留接入能力，**不在 v1 留下半成品逻辑**。扩展点 = Repository 抽象 + feature flags + 全局唯一 ID + 时间戳，详见 §4。
- **归档语义**：归档记 `archivedAt`，统计冻结于归档日；恢复后清空 `archivedAt`，恢复正常计算。
- **删除**：二次确认（弹窗「取消 / 确认删除」）。
- **本地容量防护**：物品条数设**硬上限 10,000 条**（可靠性防护，非商业额度），达到上限时录入/导入被拦截并提示，避免刷爆本地存储。
- **统计口径**：分类分布支持「价格 / 数量」双维度切换，切到哪个维度就按该维度倒序展示（已落地原型 v4）。

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | 微信小程序原生（WXML/WXSS/JS） | 目标形态即小程序；原生最轻、零构建依赖、上架简单 |
| 存储（v1） | 本地缓存 `wx.setStorageSync` | v1 纯本地，零成本、零隐私顾虑、无需联网 |
| 存储（v2+ 扩展） | 微信云开发 CloudBase（云数据库 + 云函数） | 同生态、免运维、自带鉴权；**仅替换 Repository 实现**即可接入 |
| UI | 自定义组件 + CSS 变量主题 | 已定稿 v4「极简墨」视觉；CSS 变量承载主题，便于后续浅/暗色 |
| 构建 | 无需（小程序原生） | 保持轻量；组件化用原生 `Component` |

> 结论：**v1 纯本地、零云端依赖**。量化计算、UI、分类体系与存储实现解耦；v2 接 CloudBase 时只新增一个 `CloudRepository` 实现并打开 feature flag，业务代码与计算逻辑一行不动。

## 2. 数据模型

### 2.1 物品 Item（核心实体，v1 全部字段）
```jsonc
{
  "id": "string(uuid)",     // 全局唯一 ID（uuid，为多端同步预留，v1 即采用）
  "name": "string",         // 名称 *
  "price": "number",        // 购买价格（元）*
  "date": "string",         // 购买日期 YYYY-MM-DD *
  "brand": "string",        // 品牌（选填）
  "cat": "string",          // 分类 key（见分类体系）
  "emoji": "string",        // 分类图标（冗余存储，避免查表）
  "life": "number",         // 预计使用年限（年），默认 1，可改
  "archived": "boolean",    // 是否归档（默认 false）
  "archivedAt": "string|null", // 归档时间 YYYY-MM-DD；归档时写入，恢复时置 null
  "createdAt": "string",    // 创建时间（审计/排序）
  "updatedAt": "string"     // 最后修改时间（为 v2 并发控制预留，v1 照常写入但暂不使用）
}
```
> 与《AGENTS.md》一致：**不引入「当前估值」字段**；量化指标全部由 `(price, date, life, archivedAt)` 派生计算，不落地存储（避免数据漂移）。
> `updatedAt` / `id(uuid)` 在 v1 就写入，是**为未来云同步预留的最小成本准备**，但 v1 不依赖它们做任何同步行为。

### 2.2 分类（单一数据源，可扩展）
- 分类定义在**单一配置**（`config/categories.js`）：`EMOJI` 对象 + 派生 `CATS` 数组，**顺序即展示顺序**。
- 当前 10 类：数码📱 › 汽车🚗 › 会员🎫 › 家电🔌 › 家居🛋️ › 服饰👕 › 美妆💄 › 运动⚽ › 珠宝💍 › 其它📦。
- 增删/排序**只改这一处**；筛选抽屉、录入页高频平铺（`COMMON_CATS`）、统计分布自动跟随。
- `COMMON_CATS`（高频常显，录入页平铺）：`['数码','家电','服饰','美妆','家居','运动']`。

### 2.3 用户 / 订阅实体——v1 **不存在**
> **v1 不建立任何用户、配额、订阅、plan 相关实体或字段**。本地存储只放物品数据本身。
> 这些实体（openid / quotaUsed / plan / subscribedAt 等）属于 v2+ 的扩展内容，届时在 `store/cloud.js` 与 `services/subscription.js` 中定义，v1 代码库里不出现它们的影子。

## 3. 量化计算模块（产品灵魂，纯函数）

> 关键：**归档冻结**。所有时间相关指标以「参考日 `refDate`」为基准——未归档用今天，已归档用 `archivedAt`。

```js
const TODAY = new Date();
function refDate(it){ return (it.archived && it.archivedAt) ? new Date(it.archivedAt) : TODAY; }
function daysSince(d, ref){ ref = ref || TODAY; return Math.max(0, Math.floor((ref - new Date(d))/86400000)); }
function held(it){ return daysSince(it.date, refDate(it)); }            // 持有天数（归档则冻结）
function daily(it){ const h = held(it); return h ? it.price / h : 0; }   // 日均使用价格
function loss(it){ return Math.min(100, Math.round(held(it)/(it.life*365)*100)); } // 损耗率（时间维度）
function remain(it){ return Math.max(0, it.life*365 - held(it)); }       // 剩余天数
function lossColor(l){ return l<50?'#07C160':(l<80?'#F2C037':'#EF4B4B'); } // 阈值配色
```
- 模块独立、无副作用，便于单元测试；微信端与本地脚本（如导入校验）可复用。
- 该模块与"数据来自本地还是云端"无关——这是它能跨 v1/v2 复用的关键。

## 4. 存储与扩展架构（v1 纯本地 → v2 可平滑扩展）

### 4.1 设计原则：用**接口与开关**预留扩展，而非写半成品逻辑
v1 不写订阅/云同步的任何业务代码。未来能力通过三层干净扩展点接入，业务/UI/计算零改动：

1. **Repository 抽象（存储可替换）**：定义 `IRepository` 接口，v1 用 `LocalRepository`。v2 新增 `CloudRepository`，业务层只依赖接口。
2. **Feature Flags（能力开关）**：`config/features.js` 定义 `CLOUD_SYNC: false`、`SUBSCRIPTION: false`。v1 全 `false`，UI 据此**不渲染**任何云/订阅入口；v2 置 `true` 即激活，代码可预先写好但被开关 gate 住。
3. **全局唯一 ID + 时间戳（数据层预留）**：v1 即采用 uuid + 写入 `updatedAt`，为 v2 多端合并/并发控制做准备，无需回头改数据。

### 4.2 v1 本地存储（现在就做）
```
store/
  localStore.js     // 封装 wx.getStorageSync/setStorageSync，单例读写
  repository.js     // IRepository 接口 + LocalRepository 实现：list/add/update/remove/archive/restore
```
- 全量数据存一个 key（如 `youshu:items`），读取后内存操作，变更后整体写回。
- **容量防护（硬上限 10,000 条）**：`config/limits.js` 定义 `MAX_ITEMS = 10000`。录入保存前、导入合并前都做校验，超限则拦截并提示「已达本地存储上限（10000 件），请先删除或归档部分物品」。这是**可靠性防护**（防止刷爆 `wx.setStorage` 容量），不是商业额度（商业额度属 v2 订阅）。
- 导出：`wx.getFileSystemManager` 写临时文件 + `wx.shareFile` / `wx.saveFileToDisk`（界面称「导出数据」）。
- 导入：选择文件 → 解析 JSON → 校验 schema → **按 `id` 覆盖本机**（见 §4.2.1 冲突处理），覆盖前展示"将被覆盖清单"供用户确认。

#### 4.2.1 导入冲突处理（按 id 覆盖 + 覆盖前明示清单）
- **规则**：导入数据与本机数据**按 `id` 比对**。
  - id 在本机**已存在** → 用导入数据**覆盖本机**该条（以导入为准）。
  - id 在本机**不存在** → 作为新物品**新增**。
  - 本机有、导入没有的物品 → **保留不动**（导入不是全量替换，而是按 id 合并覆盖）。
- **覆盖前必须明示（关键体验）**：解析导入文件后，先计算出"哪些本机物品会被覆盖"，弹出一个**确认弹窗**，中间是一个**可上下滚动的列表**（`max-height` + `overflow-y:auto`），逐条展示每个将被覆盖物品的**关键数据**：
  ```
  ┌── 以下 N 件物品将被导入数据覆盖 ──┐
  │ 📱 iPhone 15 Pro                  │
  │   本机：¥8,799 · 2023-09-15       │
  │   导入：¥8,299 · 2023-10-01  ← 覆盖│
  │ 🔌 戴森吹风机 HD08                 │
  │   本机：¥2,990 · 2024-01-20       │
  │   导入：¥2,690 · 2024-01-15  ← 覆盖│
  │ …（列表可滚动）                    │
  └──────────────────────────────────┘
        [ 取消 ]        [ 确认覆盖 ]
  ```
  - 列表要考虑显示美观：每条含 emoji + 名称 + 「本机值 / 导入值」对照；条数多时列表内部滚动，弹窗本身不撑破屏幕。
  - 同时汇总提示：`将覆盖 N 件、新增 M 件`。用户点「确认覆盖」才写入；「取消」则完全不改动本机数据。
- 导入总量校验：`本机保留数 + 新增数` 不得超过 `MAX_ITEMS(10000)`，超限则中止并提示。

### 4.3 v2+ 扩展点（不写在 v1，仅定义接口与位置）
```
store/
  repository.js     // IRepository 接口（v1 已定义）
  localStore.js     // LocalRepository 实现（v1 用）
  cloudStore.js     // CloudRepository 实现（v2 新增，替换存储后端）
services/
  subscription.js   // 订阅服务：微信支付 requestPayment + 额度校验（v2 新增）
  sync.js           // 增量同步/冲突合并（v2 新增，v1 为 no-op 或不存在）
config/
  features.js       // CLOUD_SYNC=false / SUBSCRIPTION=false（v2 置 true 激活）
```
- 同步策略（v2 设计）：以 `updatedAt` 做乐观并发（last-write-wins）或版本号冲突合并；免费额度、订阅价届时由服务端下发配置，不硬编码。
- **v1 与 v2 的差异仅在于**：多了一套 `CloudRepository`/`subscription`/`sync` 实现 + feature flag 置真 + 对应 UI 入口。`calc.js`、组件、分类、归档/删除逻辑完全复用。

### 4.4 目录结构（建议）
```
/miniprogram

  /store
    repository.js   // IRepository 接口 + LocalRepository

    date.js  format.js  export.js  import.js
```

## 5. 关键交互的流程要点（与已定 UI 对齐）
- **归档**：详情页「归档」→ 写 `archived=true, archivedAt=今天` → 首页与统计立即剔除 → 统计页「归档物品」模块 +N。
- **恢复**：归档页/详情「恢复」→ `archived=false, archivedAt=null` → 回到正常计算与统计。
- **删除**：点「删除/彻底删除」→ 弹二次确认框（取消/确认删除）→ 确认后才真正移除数据（不可恢复）。
- **录入**：3 必填 + 年限快捷选项 + 实时预览；分类=高频平铺(6) + 抽屉选其余（禁止横向滚动，见 AGENTS.md）。
- **数据边界**：v1 数据 100% 在本地；导出/导入是用户主动的备份与迁移手段，不涉及云。

## 6. 已确认决策（2026-07-09 定稿）
1. **统计口径** ✅：分类分布支持「价格 / 数量」双维度切换，切到哪个维度就按该维度倒序（已落地原型）。本期仍不加估值字段。
2. **本地容量上限** ✅：`MAX_ITEMS = 10000`，作为可靠性防护（防刷爆本地存储），录入与导入均校验拦截。非商业额度。
3. **ID 方案** ✅：用 uuid，v1 即采用，为未来多端同步预留。
4. **导入冲突** ✅：按 `id` 覆盖本机；覆盖前弹出**可滚动列表**明示将被覆盖的物品（含本机值 / 导入值对照 + 汇总"覆盖 N 件 / 新增 M 件"），用户确认后才写入。详见 §4.2.1。
5. **云同步 + 订阅** ✅：v1 均不做；未来做的话**两者一起做、同版本上线**，通过 Repository 抽象 + feature flags 接入，v1 不写业务代码。
