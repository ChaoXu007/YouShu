# 有数 · 安卓技术架构方案（本机 APK 测试版）

> 配套：《小程序技术架构方案》《产品定位与 MVP 规划》《AGENTS.md》。
> 状态：草案 v0.1。
> **本方案目标**：把已定稿的 v4「极简墨」原型（`prototype/v4.html` + `shared.js`）**打包成安卓 APK**，安装到你自己的安卓手机上，先本机自用 / 测试，无需上架应用商店、无需服务器。

---

## 0. 目标与约束

| 项 | 说明 |
|---|---|
| **用途** | 个人自用 + 真机测试（你本人用安卓手机） |
| **产出** | 一个可直接安装的 **debug APK**（`.apk` 文件） |
| **不需要** | 应用商店上架、后端服务器、云同步、订阅（与小程序 v1 一致：纯本地） |
| **核心诉求** | **最大化复用现有原型**（HTML/CSS/JS 已经写好且你已认可），最快拿到能装机的包 |
| **数据** | 100% 存在手机本地；支持导出/导入备份（与小程序同规格：按 id 覆盖 + 覆盖前可滚动明示清单） |
| **容量防护** | 同小程序：本地物品硬上限 `MAX_ITEMS = 10000` |

## 1. 技术选型（决策与依据）

现有资产是一套完整的 **HTML + CSS + 原生 JS** 原型（`v4.html` + `shared.js`），逻辑与 UI 都已跑通。安卓化有 4 条路线：

| 方案 | 复用现有原型 | 出 APK 速度 | 原生体验 | 学习/工作量 | 结论 |
|---|---|---|---|---|---|
| **A. Capacitor（WebView 壳）** | ⭐ 几乎 100% 直接复用 | ⭐ 最快 | 良好（WebView + 原生插件） | 低 | ✅ **推荐** |
| B. Cordova | 高（同 WebView 思路） | 快 | 一般，生态老旧 | 低 | 可选，但生态不如 Capacitor 现代 |
| C. Flutter | ❌ UI 要用 Dart 重写 | 中 | 优秀 | 中高 | 过重，不适合"快速自测" |
| D. 原生 Kotlin + Compose | ❌ 全部重写 | 慢 | 最佳 | 高 | 过度设计，个人自测不值当 |

**结论：选 A · Capacitor。** 理由：
1. **直接复用**你已认可的 v4 HTML/CSS/JS，零 UI 重写，改动最小、最快出包。
2. Capacitor 是现代主流（Ionic 团队维护），把 Web 应用包成真正的原生 App，通过官方插件访问文件系统、分享、偏好存储等原生能力，**能满足导出/导入、本地存储**。
3. 产出的是标准 Android 工程，用 Android Studio / Gradle 一键 `assembleDebug` 出 APK，装机即用。
4. **与小程序共用同一份纯逻辑层**（`calc` + `categories`），双端行为一致，后续维护成本低。

> 备注：Capacitor 仍需本机安装 **JDK + Android SDK**（通过 Android Studio 一次装好），这是任何安卓打包都绕不开的。

## 2. 整体架构

```
┌─────────────────────────────────────────────┐
│                Android APK (有数)             │
│  ┌───────────────────────────────────────┐  │
│  │  Capacitor 原生壳 (MainActivity)       │  │
│  │  ┌─────────────────────────────────┐  │  │
│  │  │  WebView                         │  │  │
│  │  │  ├─ index.html (= v4 极简墨 UI)  │  │  │
│  │  │  ├─ app.css   (v4 皮肤)          │  │  │
│  │  │  ├─ core/  纯逻辑（与小程序共享） │  │  │
│  │  │  │    calc.js / categories.js    │  │  │
│  │  │  └─ platform/  安卓适配层         │  │  │
│  │  │       repository.android.js      │  │  │
│  │  └─────────────────────────────────┘  │  │
│  │        ▲ Capacitor Bridge ▼           │  │
│  │  原生插件：Preferences / Filesystem /  │  │
│  │           Share / App                  │  │
│  └───────────────────────────────────────┘  │
│         数据：手机本地（无网络、无服务器）      │
└─────────────────────────────────────────────┘
```

- **表现层**：直接是 v4 的 HTML/CSS（`v4.html` 拆成 `index.html` + 外链 css/js）。
- **逻辑层**：`core/` 里是与小程序**完全共享**的纯函数（量化计算、分类数据源），不依赖任何平台 API。
- **平台适配层**：`platform/repository.android.js` 实现统一的 `IRepository` 接口（与小程序架构 §4 一致），底层调用 Capacitor 插件读写手机本地。

## 3. 代码复用策略（与小程序同源）

把原型现有代码切成 3 块，明确哪些跨端共享：

| 模块 | 内容 | 小程序 | 安卓(Capacitor) | 是否共享 |
|---|---|---|---|---|
| **core（纯逻辑）** | 量化计算 `calc.js`、分类单一数据源 `categories.js`、`MAX_ITEMS` | ✅ | ✅ | **100% 共享**（纯 JS，无 DOM/无平台 API） |
| **UI（视图）** | v4 的 HTML/CSS | WXML/WXSS（需转写） | HTML/CSS（直接用） | 不共享 DOM，但**视觉规范共享**（配色/间距/组件形态） |
| **platform（存储/文件）** | Repository 实现 | `wx.setStorageSync` | Capacitor Preferences/Filesystem | 接口共享、实现各异 |

> 关键：`shared.js` 目前把"计算 + DOM 渲染 + 存储"混在一起。安卓工程里会做一次轻度拆分——把纯计算与分类抽到 `core/`，DOM 与存储各归其位。这样双端只维护**一份 core**，行为绝不跑偏。

## 4. 数据与存储

### 4.1 数据模型（与小程序完全一致）
沿用 `Item`：`id(uuid) / name / price / date / brand / cat / emoji / life / archived / archivedAt / createdAt / updatedAt`。量化指标全部派生计算、不落地。归档冻结、删除二次确认逻辑与小程序一字不差（复用 core）。

### 4.2 本地存储实现
- 首选 **`@capacitor/preferences`**（键值存储，简单可靠）：全量数据存一个 key（`youshu:items`），读进内存操作、变更后整体写回——与小程序 `localStore` 思路一致。
- 数据量大时可选升级 **SQLite 插件**（`@capacitor-community/sqlite`）；但 1 万条上限内，Preferences（本质是文件/SharedPreferences）足够，先用它。
- **容量防护**：录入保存前、导入合并前校验 `MAX_ITEMS = 10000`，超限拦截提示。

### 4.3 导出 / 导入（与小程序同规格）
- **导出**：`@capacitor/filesystem` 写 JSON 到应用目录 + `@capacitor/share` 拉起系统分享（存到"文件"/发给自己/存网盘）。界面仍称「导出数据」，不暴露 JSON。
- **导入**：选文件 → 解析 → 校验 schema → **按 id 覆盖本机**；覆盖前弹**可滚动列表**逐条明示将被覆盖物品（本机值 / 导入值对照 + 汇总"覆盖 N 件 / 新增 M 件"），确认后写入。规则同《小程序技术架构方案》§4.2.1。

## 5. 工程结构（建议）

```
/android-app                 # 独立安卓工程目录（与 /miniprogram 平级）
  /web                       # WebView 加载的前端资源（Capacitor 的 webDir）
    index.html               # = v4 极简墨 UI（由 v4.html 转来）
    /assets
      app.css                # v4 皮肤
    /core                    # ★ 与小程序共享的纯逻辑
      calc.js                # 量化计算（纯函数）
      categories.js          # 分类单一数据源 + COMMON_CATS
      limits.js              # MAX_ITEMS = 10000
    /platform
      repository.js          # IRepository 接口
      repository.android.js  # 基于 Capacitor 插件的实现
      exportImport.js        # 导出/导入 + 覆盖清单
    app.js                   # 页面装配、事件绑定（由 shared.js 的 UI 部分转来）
  capacitor.config.json      # appId=com.youshu.app / appName=有数 / webDir=web
  package.json               # capacitor 依赖与脚本
  /android                   # `npx cap add android` 生成的原生工程（Gradle）
```

## 6. 环境准备与打包流程（拿到 APK 的完整步骤）

> 目标：在你的电脑上产出 debug APK，传到安卓手机安装。以下命令为方案说明，正式执行时我会带你一步步跑通。

### 6.1 一次性环境准备
1. **Node.js**（已具备）。
2. **JDK 17**（Android Gradle Plugin 要求）。
3. **Android Studio**（内含 Android SDK、平台工具、Gradle）——安装后在 SDK Manager 里装好一个 Android 平台（如 API 34）。
4. 配置环境变量 `ANDROID_HOME` 指向 SDK 目录。

### 6.2 初始化 Capacitor 工程（一次性）
```bash
cd android-app
npm init -y
npm i @capacitor/core @capacitor/cli
npm i @capacitor/preferences @capacitor/filesystem @capacitor/share @capacitor/app
npx cap init 有数 com.youshu.app --web-dir=web
npx cap add android
```

### 6.3 每次改完前端后
```bash
npx cap sync android         # 把 web/ 同步进原生工程
```

### 6.4 出 APK（两种方式，任选）
- **命令行（快）**：
  ```bash
  cd android
  ./gradlew assembleDebug
  # 产物：android/app/build/outputs/apk/debug/app-debug.apk
  ```
- **Android Studio（直观）**：`npx cap open android` 打开工程 → Run 直接装到连了 USB 的手机，或 Build → Build APK(s)。

### 6.5 装到你的安卓手机
- **方式一（推荐，最快反复调试）**：手机开「开发者选项 → USB 调试」，数据线连电脑，Android Studio 点 Run 直接安装运行。
- **方式二（纯离线）**：把 `app-debug.apk` 传到手机（微信/网盘/数据线），点开安装（需允许"安装未知来源应用"）。debug 包自带调试签名，个人自测可直接装。

> release 正式签名（`assembleRelease` + keystore）本机自测阶段**不需要**，等要给别人用或上架再做。

## 7. 与小程序的关系（一套产品，两个外壳）

```
        ┌─────────── 共享 core（纯 JS）───────────┐
        │  calc.js（量化计算）· categories.js（分类）│
        │           · limits.js（10000 上限）        │
        └───────────────────┬──────────────────────┘
              ┌─────────────┴─────────────┐
        微信小程序外壳                 安卓 Capacitor 外壳
        WXML/WXSS + wx.* 存储          HTML/CSS + Capacitor 插件存储
        （上架微信生态）                （本机 APK 自测）
```

- **core 只写一次**，双端共用，保证"日均价格 / 损耗率 / 归档冻结 / 分类"行为完全一致。
- **未来云同步 + 订阅**（两者一起做）：同样通过 `IRepository` 增加 `CloudRepository` + feature flag 接入，小程序和安卓端都能复用同一套云端逻辑，两个外壳只各自加同步入口 UI。
